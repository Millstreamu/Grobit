# Grobit — v0.4 Direction Roadmap

Build plan for the design captured in `docs/DESIGN_SPEC.md §0.2` (the chronological UX/flesh-out
brainstorm, 2026-10). Ordered **cheap high-impact first, big systems after**, with dependencies noted.
This is a sequencing guide, not a contract — slices can be resequenced.

Size legend: **S** small (hours) · **M** medium (a session) · **L** large (multi-session) · **XL** the big ones.
Status: `[ ]` todo · `[~]` in progress · `[x]` done.

Current build (for contrast) still uses: 8×8 factory grid + conveyors; autonomous goblins; auto-fire
turret; one 4-tab System Terminal; no Heat/doors/spawners; instant death; no title screen. The economy
rework (Food recruit, materials build/upgrade, Tech Data = unlocks) is **already done** — see the
colony-harvest memo.

## Phase 0 — Quick wins (small, mostly independent — do first)

- [x] **0.1 Manual-fire turret** (S) — DONE. `PlayerCombat` fires on `is_action_just_pressed("attack")`
  (tap Space/LMB = one shot; cooldown caps the rate); auto-aim + Tab-pick + loader fire-rate kept;
  `grobit_abilities` no longer triggers on `attack` (field abilities dormant → Phase 5); HUD hint
  updated. No new input action needed — reused `attack` (Space/LMB).
- [x] **0.2 Remove the dead field-ability system** — DONE. The ability "picker" was actually a
  RepairStation reward (`AbilityChoicePanel`), and since 0.1 freed Space from abilities, picked abilities
  couldn't be used. Removed it all: deleted `ability_choice_panel.gd` + `grobit_abilities.gd` and the
  Grobit `Abilities` node; stripped `hud.gd` (`_abilities`/`_ability_choice`/`open_ability_choice`/ability
  status line/debug equip), `run_state.gd` (`equipped_ability`/`available_abilities`/`unlock_ability`/
  `first_locked_ability` + begin_run setup); RepairStation's old "ability" reward now grants +5 HP
  (tactical abilities return via bay modules in Phase 5). Clean import; no test impact. (`abilities.json`
  left as now-unused data.)
- [x] **0.3 Run summary card on return** (M) — DONE. The end-of-run card (`hud._summary_text`) now opens
  with a **"This run"** recap: scrap hauled, machines recovered, recipes discovered, goblins lost (names),
  and **Peak Heat** survived (with tier label). Per-run stats live in `RunState.run_stats` (reset in
  `begin_run`): `scrap_hauled`/`machines_hauled` counted in `run_controller._extract`, `goblins_lost` via
  `RunState.note_goblin_lost` (from `HarvestMode.on_goblin_lost`), `heat_peak` via `add_heat`, and recipe
  discoveries diffed against a run-start book snapshot (`recipes_discovered_this_run`). The card was
  re-laid-out (compact recap, wrapped lair-needs/resources lines, merged Tech-Data line, smaller font) so
  the whole thing — down to `[Enter] start a new run` — fits the 448px canvas. Test: `run_summary_test`.

## Phase 1 — Buildable lair + station split (L) ✅ CORE DONE

The single System Terminal is retired; the lair is built from **buildable station objects**. (Big-bang
rewrite; stations grouped.) See `data/game/stations.json`.

- [x] **1.1 Station objects + focused panels** — DONE. `LairStation` (`scripts/world/lair_station.gd`,
  one `InteractableObject` per station, def-driven) routes `[F]` → `Hud.open_station(type)`. Panels are
  REUSED: Workshop→`FactoryPanel`, Process Line→`ProcessWorkshopPanel`, Fabricator→`FabricatorPanel`,
  Component Exchange→`ExchangePanel`, and **Goblin Quarters / Upgrade Bench / Mission Board** →
  `LairPanel.open_section("goblins"|"upgrades"|"tasks")`. `LairPanel` was repurposed from a 4-tab window to
  a **section-locked** panel (tab strip + embedded FactoryPanel removed; section logic + row helpers +
  `UPGRADABLE` kept). `SystemTerminal` retired (unused).
- [x] **1.2 Buildable placement + persistence** — DONE. `BuildManager` ([B]) builds **stations** at the
  lair (`not RunState.driving`) and field buildables out on a run: context-aware palette, cost from the
  def (Workshop + Mission Board free), place via `LairStation`, **remove** by pressing place on an existing
  station (move = remove + rebuild; no refund). Layout persists in `MetaState.lair_stations` ([{type,x,y}],
  saved/loaded); `RunController._spawn_lair_stations` seeds the free defaults (Workshop + Mission Board) on
  a fresh lair and restores the saved layout every run. HUD hint added. Test: `lair_stations_test`.
- [x] **1.3 Fold in existing stations** — DONE for **Fabricator + Component Exchange** (buildable lair
  stations). Repair stays a field reward station (not a lair build).
- [ ] **1.4 Soft sequence** — Mission Board gates/suggests the unique builds in order; free building after.
  *Deferred* (needs the Mission Board to drive build order). *Also deferred:* per-upgrade station split;
  station art (placeholders for now, see `docs/ART_REQUIRED.md`).

## Phase 2 — Heat & the expedition (L–XL) ✅ COMPLETE

The core new tension layer. All four slices done; sweep green. Remaining polish folded into later beats:
per-door difficulty/alarm from `area_generator`, and the cross-room retreat gauntlet (Beat-5 extraction).

- [x] **2.1 Heat meter** — DONE. `RunState.heat` (0–`HEAT_MAX` 100), `add_heat`/`heat_ratio`/`heat_tier`
  (CALM / BOT_THREAT ≥55 / FULL_ALERT ≥80), resets in `begin_run`, never decays in play. Rises in
  `HarvestMode.advance_siege` while a breach is live with enemies about (`HEAT_RISE_PER_SEC`), not while
  recalling. HUD Heat bar (`_update_heat`, top-centre, tier-coloured). Test: `heat_test`. *Next:* 2.4
  makes the thresholds actually change which enemies spawn.
- [x] **2.2 Bot HP + game-over + save-on-return** — DONE. Grobit IS the bot (HealthComponent; `died` →
  `_on_player_died`); tier-2 bruisers (2.4) damage it; at 0 HP → `_end_run(RESULT_LOST)` → game over, and
  respawn beacons are never spawned so death always ends the run. **`_end_run` now saves the snapshot ONLY
  on a return** (extract/ship/rescue) — a LOST run doesn't save, so reloading reverts to your last return
  (you forfeit the run's haul; goblin permadeath, saved when it happens, stays). Test: `save_return_test`.
- [x] **2.3 Doors + hacking minigame** — DONE. `HackSession` (logic: match switches → stop the circular
  timing marker in the green → crack → reveal alarm → Open/Skip; miss = fail; difficulty scales pattern
  length + dial tightness/speed). `HackPanel` renders all three stages + outcome. `Door` (field only,
  `RunState.driving`): `[F]` launches the hack; crack+open adds `alarm` Heat; botched = +12 Heat spike +
  6s jam; lair doors unchanged. HUD routes `open_hack` + input ownership. Tests: `hack_session_test`.
  *Still to do:* `area_generator` should set per-door `difficulty`/`alarm` (currently defaults 1 / 15).
- [x] **2.4 Spawners + two enemy tiers keyed to Heat** — DONE. `SiegeEnemy.setup_tier(1|2)`: tier-1
  grunts hunt goblins; tier-2 bruisers (tankier/harder) go for the SCRAPBOT and appear once Heat crosses
  HEAT_BOT_THREAT (`HarvestMode._roll_enemy_tier`). `Spawner` (destructible, on the turret's hit layer):
  a breach plants one at each door; wreck them all below full alert to CUT the flow (relief), but
  FULL_ALERT hardens them (can't drop, wrecked ones re-source). Tests: `enemy_tier_test`, `spawner_test`.
  *Still to do:* the retreat gauntlet (enemies path from spawners across rooms while driving home) belongs
  with Beat-5 extraction; `area_generator` per-door difficulty/alarm.

## Phase 3 — In-room command layer (L) ✅ COMPLETE

- [x] **3.1 Embodiment / planted** — DONE. While deployed the bot is PLANTED (`deploy` →
  `bot.set_input_locked(true)`, `_end_siege` unlocks), so WASD drives the command cursor, not the bot.
- [x] **3.2 Goblins idle-until-commanded + task model** — DONE. `HarvesterGoblin` reworked from
  autonomous `_seek`-nearest to COMMANDED: `assigned_target` drives it; no assignment → idle at the bot
  (no auto-grabbing uncommanded piles). `has_valid_assignment`/`can_work`/`is_idle` helpers. `HarvestMode`
  task API: `command_target` (registers a task in priority order + puts one more idle, capable goblin on
  it per call), `cancel_target` (pulls all off), `reassign_idle` (idle goblins flow to the next priority
  task), `goblins_on`/`task_count`. Auto-haul when full then resume the same target. Test: `command_test`
  (+ updated `goblin_work_test`/`harvest_test`/`harvest_playtest` to command instead of relying on autonomy).
- [x] **3.3 Command cursor UI + input** — DONE. `HarvestMode` owns a WASD **command cursor** (bounded to a
  radius around the parked bot): `[F]` → `command_target` under it, `[Esc]` → `cancel_target`.
  `HarvestMode._draw` renders the crosshair (green over a valid target), a cyan target highlight, per-task
  **goblin-count badges**, and an idle readout. `SelectionManager` yields `[F]` while a harvest is active.
  *Deferred:* floor-loot-as-a-target (goblins gathering floor drops) — a small follow-up.

## Phase 4 — Production redesign (XL — the big one)

Replace the recycler/conveyor factory with assembly-line chains.

- [x] **4.1–4.3 Chain ENGINE (core logic)** — DONE. `process.json` (verbs heat/press/mold/fold + sequence
  recipes, some `known:true`); `GameData.process_recipe`/`process_product` (match scrap + exact verb order);
  `ProcessGrid` (RefCounted): `set_intake`, `place(verb,pos,in_dir,out_dir)`, `trace_sequence()` (walks the
  chain, following ONLY aligned ports — misaligned/gap/loop breaks it), `output_cell`, `product_for`.
  Product = f(input scrap, ordered verbs); fluid (recomputed each call); no conveyors. Test:
  `process_chain_test` (straight chain, input-matters, fluid swap, misalign kills it, gap stops it, L-bend
  works, no-intake). *Built ALONGSIDE the old factory_grid, which still runs.*
- [~] **4.4 Recipe book + processing + UI** — IN PROGRESS.
  - [x] **Chain processor** — `ProcessGrid.tick(delta, inv)`: intake carries a scrap TYPE; a valid chain
    consumes 1 scrap and makes 1 product per recipe cycle; `status` idle/working/blocked; `progress_ratio`;
    fluid (re-resolves the product each tick). `inv` = anything with `get_quantity`/`add`. Test:
    `process_run_test`.
  - [x] **Recipe book (hybrid)** — DONE (data/model). `MetaState.discovered_recipes` (persisted) +
    `is_recipe_known` (starter `known:true` OR discovered), `discover_recipe` (logs on first make,
    emits `changed`), `known_recipes()` (book contents in order). `ProcessGrid.tick` calls
    `discover_recipe(product)` on cycle completion. Test: `recipe_book_test`. *A book UI comes with the
    Workshop UI.*
  - [x] **Workshop UI** — DONE + INTEGRATED. Editor (`ProcessWorkshopPanel`): 8×6 grid; tool palette
    (Intake / Heater / Presser / Molder / Folder / Erase); [WASD] cursor, [Tab] tool, [Space] place, [R]
    rotate (machine or placement facing), [Enter] cycle intake scrap, [Esc] close. Draws the proc art +
    in/out arrows, the live chain highlight, the OUT cell, the "Line → Makes: <product>" readout, and the
    recipe book. `ProcessGrid.chain_cells()`/`rotate()` added; renders with the hand-authored proc art.
    **Integration:** `RunState.process_grid` (a persisted `ProcessGrid`, created in `begin_run`, loaded over
    by `RunController` from `MetaState.process_blob` via `ProcessGrid.to_data`/`from_data`); a new **Workshop
    tab** in the System Terminal (`LairPanel`) previews the live line + recipe book and launches the modal
    editor (`Hud.open_process_workshop`); `FactoryProcessor` ticks the line at the lair only (`not driving`),
    consuming scrap from and dropping products into the shared run inventory (firing recipe-book discovery).
    The chain products (steel_plate/ingot/spring, copper_sheet/coil, plastic_casing, ceramic_tile) are now
    real resources in `resources.json`. Test: `process_integration_test`.
  - [~] **Economy swap** — IN PROGRESS (staged; full chain economy + multi-line, user's call). Each stage green.
    - [x] **4A multi-line ProcessGrid** — `intakes` array (several parallel chains per grid); `tick` advances
      each line; per-intake trace/output/product; `to_data`/`from_data` migrate old single-intake blobs. The
      Workshop editor (`ProcessWorkshopPanel`) places multiple intakes + draws every line. Tests updated
      (`process_chain_test` multi-line, etc.).
    - [x] **4B products get every role** — `process.json` recipes so chains make the 4 base products + the 4
      ammo (`charge_cells`/…) + the 4 components (`reinforced_frame`/…); ammo/component ids reused (no
      resource changes). Test: `process_recipes_test`.
    - [x] **4C re-point the economy** — `TIER_MATERIAL`/`_upgrade_material`/`expand_cargo_cost` + station +
      module + cache costs now pay in base products (steel_plate/copper_sheet/…). Raw materials are legacy.
      Cost-related tests updated.
    - [x] **4D retire the old factory** — DONE. Removed recyclers/ammo-makers/component-makers/junk +
      all recipes (`recipes.json` → `[]`; `machines.json` → bay modules only). Find/repair categories →
      Weapon + Ammo Loader + Support Module (bay) only; guaranteed-recycler chain + field Component Exchange
      retired. `FactoryProcessor` no longer ticks the factory grid (it's pure inventory now);
      `_seed_starter_line` seeds a steel→heat→press starter chain. Workshop + Exchange stations retired →
      **Process Line is the free, pre-placed production station**; Upgrade Bench is Tech+cargo only;
      Fabricator crafts support modules only. Deleted ~16 retired-system tests, rewrote
      `fabricator_test`/`cell_stack_test`/`lair_stations_test`; added `economy_swap_test` (end-to-end:
      chains make currency/ammo/components, each spent in its role). Sweep green.

**PHASE 4 COMPLETE** — the process lines are the whole economy; the old conveyor/recycler factory is gone.

## Phase 5 — Module → ability catalogue (M–L) ✅ COMPLETE

- [x] **5.1 Ability modules** — DONE. Three support bay modules in `machines.json`, each with an
  `ability` hook: **Coolant Vent** (reduce_heat −10), **Medbay** (heal_goblins +2), **Scanner** (scan a
  nearby room's salvage). Abilities are **tactical + non-twitch**, fired with **[1]–[3]** from the
  ScrapbotPanel's abilities strip (the old hardcoded placeholder strip is gone). Powered by **per-run
  CHARGES** (summed across stacked modules, refilled at the lair): `RunState.installed_abilities` /
  `ability_max` / `ability_remaining` / `use_ability`, `ability_used` reset in `begin_run`. Effects —
  reduce_heat via `add_heat(-n)` (clamps, no charge if already calm); heal_goblins heals deployed
  `harvester_goblins` (`HarvesterGoblin.heal`/`needs_heal`); scan picks the nearest un-scanned, un-cleared
  salvage room and logs `Room.loot_summary()` to the HUD (`Room.scanned`). Field-only gating on Heal/Scan.
  The modules are **craftable at the Fabricator** (bay modules → machine-instance storage → equip in the
  bay). Test: `module_ability_test`. (Field-ability-on-Space and the run-start picker were already removed
  in Phase 0.1/0.2.) *Possible follow-ups:* module icons (art), a scan marker on the minimap.

  Mission Board (`intro_recruit`/`intro_build`/`intro_craft`) using two new goal types (`stations`,
  `recipes`). Test: `cold_open_test`. (Heavier dedicated tutorial = later.)

## Recommended sequence
0 (now) → 2 (the tension that defines the game) → 3 (makes rooms active) → 5 (abilities round out combat/
utility) → 1 (base-building flesh-out) → 6 (wrap the new-player experience) → 4 (the production rewrite,
when ready — it's the riskiest and the current factory keeps working meanwhile). Reorder to taste.
