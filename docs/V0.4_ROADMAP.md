# Grobit — v0.4 Direction Roadmap

Build plan for the design captured in `docs/DESIGN_SPEC.md §0.2` (the chronological UX/flesh-out
brainstorm, 2026-10). Ordered **cheap high-impact first, big systems after**, with dependencies noted.
This is a sequencing guide, not a contract — slices can be resequenced.

Size legend: **S** small (hours) · **M** medium (a session) · **L** large (multi-session) · **XL** the big ones.
Status: `[ ]` todo · `[~]` in progress · `[x]` done.

Current build (for contrast) still uses: 8×8 factory grid + conveyors; autonomous goblins; auto-fire
turret; one 4-tab System Terminal; no Heat/doors/spawners; instant death; no title screen. The economy
rework (Food recruit, materials build/upgrade, Tech Data = unlocks) is **already done** — see the
colony-harvest memo.

## Phase 0 — Quick wins (small, mostly independent — do first)

- [x] **0.1 Manual-fire turret** (S) — DONE. `PlayerCombat` fires on `is_action_just_pressed("attack")`
  (tap Space/LMB = one shot; cooldown caps the rate); auto-aim + Tab-pick + loader fire-rate kept;
  `grobit_abilities` no longer triggers on `attack` (field abilities dormant → Phase 5); HUD hint
  updated. No new input action needed — reused `attack` (Space/LMB).
- [ ] **0.2 Remove the run-start ability picker + field ability-on-Space** (S–M). Abilities will come
  from bay modules later (Phase 5); for now strip the picker and the Space=ability binding so Space is
  free to shoot and the cold open is cleaner. *Touches:* `hud.gd` (open_ability_choice), `run_controller`
  setup, `run_state` ability fields, `ability_choice_panel`. *Depends:* 0.1 (so Space has a job).
- [ ] **0.3 Run summary card on return** (M). On a successful extract, show scrap hauled, goblins lost
  (→ memorial), recipes/machines discovered, Heat survived — before dropping back into the lair.
  *Touches:* new panel, per-run stat tracking, `run_controller._extract`. *Depends:* none (Heat line is
  a later add).

## Phase 2 — Heat & the expedition (L–XL) ✅ COMPLETE

The core new tension layer. All four slices done; sweep green. Remaining polish folded into later beats:
per-door difficulty/alarm from `area_generator`, and the cross-room retreat gauntlet (Beat-5 extraction).

- [x] **2.1 Heat meter** — DONE. `RunState.heat` (0–`HEAT_MAX` 100), `add_heat`/`heat_ratio`/`heat_tier`
  (CALM / BOT_THREAT ≥55 / FULL_ALERT ≥80), resets in `begin_run`, never decays in play. Rises in
  `HarvestMode.advance_siege` while a breach is live with enemies about (`HEAT_RISE_PER_SEC`), not while
  recalling. HUD Heat bar (`_update_heat`, top-centre, tier-coloured). Test: `heat_test`. *Next:* 2.4
  makes the thresholds actually change which enemies spawn.
- [x] **2.2 Bot HP + game-over + save-on-return** — DONE. Grobit IS the bot (HealthComponent; `died` →
  `_on_player_died`); tier-2 bruisers (2.4) damage it; at 0 HP → `_end_run(RESULT_LOST)` → game over, and
  respawn beacons are never spawned so death always ends the run. **`_end_run` now saves the snapshot ONLY
  on a return** (extract/ship/rescue) — a LOST run doesn't save, so reloading reverts to your last return
  (you forfeit the run's haul; goblin permadeath, saved when it happens, stays). Test: `save_return_test`.
- [x] **2.3 Doors + hacking minigame** — DONE. `HackSession` (logic: match switches → stop the circular
  timing marker in the green → crack → reveal alarm → Open/Skip; miss = fail; difficulty scales pattern
  length + dial tightness/speed). `HackPanel` renders all three stages + outcome. `Door` (field only,
  `RunState.driving`): `[F]` launches the hack; crack+open adds `alarm` Heat; botched = +12 Heat spike +
  6s jam; lair doors unchanged. HUD routes `open_hack` + input ownership. Tests: `hack_session_test`.
  *Still to do:* `area_generator` should set per-door `difficulty`/`alarm` (currently defaults 1 / 15).
- [x] **2.4 Spawners + two enemy tiers keyed to Heat** — DONE. `SiegeEnemy.setup_tier(1|2)`: tier-1
  grunts hunt goblins; tier-2 bruisers (tankier/harder) go for the SCRAPBOT and appear once Heat crosses
  HEAT_BOT_THREAT (`HarvestMode._roll_enemy_tier`). `Spawner` (destructible, on the turret's hit layer):
  a breach plants one at each door; wreck them all below full alert to CUT the flow (relief), but
  FULL_ALERT hardens them (can't drop, wrecked ones re-source). Tests: `enemy_tier_test`, `spawner_test`.
  *Still to do:* the retreat gauntlet (enemies path from spawners across rooms while driving home) belongs
  with Beat-5 extraction; `area_generator` per-door difficulty/alarm.

## Phase 3 — In-room command layer (L)

- [ ] **3.1 Embodiment** — in a room you ARE the planted bot/turret (no Grobit-on-foot); confirm/adjust
  player control split (WASD cursor vs. movement).
- [x] **3.2 Goblins idle-until-commanded + task model** — DONE. `HarvesterGoblin` reworked from
  autonomous `_seek`-nearest to COMMANDED: `assigned_target` drives it; no assignment → idle at the bot
  (no auto-grabbing uncommanded piles). `has_valid_assignment`/`can_work`/`is_idle` helpers. `HarvestMode`
  task API: `command_target` (registers a task in priority order + puts one more idle, capable goblin on
  it per call), `cancel_target` (pulls all off), `reassign_idle` (idle goblins flow to the next priority
  task), `goblins_on`/`task_count`. Auto-haul when full then resume the same target. Test: `command_test`
  (+ updated `goblin_work_test`/`harvest_test`/`harvest_playtest` to command instead of relying on autonomy).
- [ ] **3.3 Command cursor UI + input** — WASD command cursor (while deployed), **F** on a target →
  `command_target`, a Cancel key → `cancel_target`, visuals (cursor, task markers, goblin counts), and the
  planted-while-deployed gating (3.1). Floor-loot gathering as a target type. *The data model (above) is
  done; this is the player-facing layer.* *Touches:* new command-cursor UI, Grobit movement gate.

## Phase 4 — Production redesign (XL — the big one)

Replace the recycler/conveyor factory with assembly-line chains.

- [ ] **4.1 Process-verb machines** — Heater / Presser / Molder / Folder…, uniquely shaped, in/out ports
  on edges. *Touches:* `machines.json`, `factory_grid.gd`.
- [ ] **4.2 Connected chains** — item flows only where out-port ↔ in-port **line up** on touching edges;
  no conveyors; misaligned = dead chain. Mostly 1-in/1-out; rare multi-port advanced machines.
- [ ] **4.3 Sequence recipes** — product = f(input scrap type, ordered verb sequence); ~1–3 products per
  grid; fluid rearrange. *Touches:* new recipe model (replaces `recipes.json` shape).
- [ ] **4.4 Recipe book (hybrid)** — a few known starters + discovered-by-experiment recipes logged.
  *Depends:* Workshop station (1.1). *Risk:* very high (biggest single rewrite; the current factory
  keeps working until this lands).

## Phase 5 — Module → ability catalogue (M–L)

- [ ] **5.1 Ability modules** — bay modules grant **tactical, non-twitch** abilities used from the
  ScrapbotPanel: Scan (reveal a room's loot), Reduce Heat −N, Heal Goblins, … The bay "abilities strip"
  becomes the real usable list. *Touches:* `machines.json` (module defs + ability hooks),
  `scrapbot_panel.gd`, Heat/goblin systems for effects. *Depends:* 2.x (Heat/Scan), 3.x (Heal), the
  module bay (exists).

## Phase 6 — Cold open & onboarding (M–L)

- [ ] **6.1 Title/main menu** + one-line premise; **debug save** entry (a pre-built lair for testing).
- [ ] **6.2 Guided first run** — each station teaches itself on first use (contextual nudges), driven by
  the Mission Board's opening sequence. (Heavier dedicated tutorial = later.) *Depends:* Phase 1 (lair
  + Mission Board). *Risk:* med.

## Recommended sequence
0 (now) → 2 (the tension that defines the game) → 3 (makes rooms active) → 5 (abilities round out combat/
utility) → 1 (base-building flesh-out) → 6 (wrap the new-player experience) → 4 (the production rewrite,
when ready — it's the riskiest and the current factory keeps working meanwhile). Reorder to taste.
